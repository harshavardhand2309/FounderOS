### ⚠️ The one trap that breaks everything

`.github/workflows/analytigo-pages.yml` builds with `ANALYTIGO_BASE=/FounderOS/`
because GitHub Pages serves from a subpath. **Firebase Hosting serves from the
domain root.** If you build with that variable set, every JS, CSS and image URL
gets a `/FounderOS/` prefix and the deployed site is a blank page with 404s in
the console.

Always build for Firebase with `ANALYTIGO_BASE` **unset**:

```bash
cd analytigo
unset ANALYTIGO_BASE
npm run build
```

Verify before deploying — this must print `/assets/…`, never `/FounderOS/assets/…`:

```bash
grep -o 'src="[^"]*"' dist/index.html
```

## 5. [AGENT] Create the deploy config

### `analytigo/firebase.json`

```json
{
  "hosting": {
    "public": "dist",
    "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
    "cleanUrls": true,
    "trailingSlash": false,
    "appAssociation": "NONE",

    "rewrites": [
      { "source": "**", "destination": "/index.html" }
    ],

    "headers": [
      {
        "regex": "^/assets/.*-[A-Za-z0-9_-]{8}\\.(js|css)$",
        "headers": [
          { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
        ]
      },
      {
        "source": "/assets/**/*.@(jpg|jpeg|png|webp|avif|svg|mp4|webm|glb|woff2)",
        "headers": [
          { "key": "Cache-Control", "value": "public, max-age=86400, stale-while-revalidate=604800" }
        ]
      },
      {
        "source": "/index.html",
        "headers": [
          { "key": "Cache-Control", "value": "no-cache, max-age=0, must-revalidate" }
        ]
      },
      {
        "source": "/",
        "headers": [
          { "key": "Cache-Control", "value": "no-cache, max-age=0, must-revalidate" }
        ]
      },
      {
        "source": "**",
        "headers": [
          { "key": "X-Content-Type-Options", "value": "nosniff" },
          { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
          { "key": "X-Frame-Options", "value": "SAMEORIGIN" },
          { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=()" }
        ]
      }
    ]
  },

  "firestore": {
    "rules": "firestore.rules"
  },

  "storage": {
    "rules": "storage.rules"
  }
}
```

**Why each part matters:**

- The `rewrites` catch-all is what makes `/tennis`, `/privacy`, `/careers/:id` survive
  a refresh. Without it, every deep link 404s. Real files in `dist` still win — the
  rewrite only catches paths that don't match a file.
- The `regex` cache rule targets **only Vite's content-hashed files** (`index-a1B2c3D4.js`).
  Files in `public/assets/` keep their names across deploys, so caching those as
  `immutable` would pin stale images and videos in browsers for a year. That's why
  there are two separate rules and not one blanket `/assets/**`.
- `/index.html` **and** `/` both need `no-cache` — Firebase treats them as separate
  routes even with the SPA rewrite. Miss either and a deploy won't show up.

### `analytigo/storage.rules`

**This file does not exist yet and its absence is a live bug.** The careers page
uploads CVs to Cloud Storage (`analytigo/src/utils/firebase.js` → `submitApplication`,
which calls `uploadBytes` to `resumes/{roleId}/…`). Applicants are not signed in, so
Firebase's default rules reject every upload — but loosening them naively gives you
an open file drop on the public internet.

```
rules_version = '2';

service firebase.storage {
  match /b/{bucket}/o {

    // Job application CVs — write-once, never listed or read by clients.
    match /resumes/{roleId}/{fileName} {
      allow create: if request.resource.size < 10 * 1024 * 1024
                    && request.resource.contentType.matches(
                         'application/pdf|application/msword|application/vnd.openxmlformats-officedocument.wordprocessingml.document'
                       );
      allow read, update, delete: if false;
    }

    match /{allPaths=**} {
      allow read, write: if false;
    }
  }
}
```

> **Known limitation, tell the owner:** `submitApplication` calls `getDownloadURL()`
> immediately after uploading, which needs *read* access to the object it just wrote.
> These rules deny that, so the upload succeeds but the stored `resumeUrl` will be
> empty. Read CVs from the Firebase console instead. Granting public read on
> `resumes/` would make every applicant's CV downloadable by anyone with the URL —
> don't. The proper fix is a Cloud Function using the Admin SDK, which bypasses rules.

### Existing `firestore.rules` — leave it alone

Already correct. It lets the public site **write** leads but never **read** them back,
so nobody can scrape the waitlist. Collections: `waitlist`, `contact_messages`,
`job_applications`, `users`, `signin_events`.

## 7. [OWNER] Connect thelvlupsports.com

Firebase console → **Hosting → Add custom domain**.

**Recommended shape:** add `www.thelvlupsports.com` first as the content domain.
Then add `thelvlupsports.com` and tick *"redirect to another domain"* pointing at
`https://www.thelvlupsports.com`. (Or the reverse — pick one, redirect the other, so
you never serve both and split your SEO.)

Firebase will print the DNS records to add. **Use exactly what it prints.** Typically:

| Purpose | Type | Host | Value |
|---|---|---|---|
| Ownership | `TXT` | `@` | `hosting-site=…` (generated per project) |
| Apex → Hosting | `A` | `@` | the IPs the console shows — add every one |
| www → Hosting | `A` or `CNAME` | `www` | as shown, or `<site>.web.app` |

**Things that actually go wrong:**

- **Keep the TXT verification record forever.** It authorises SSL *renewal*. Deleting
  it months later silently breaks your certificate.
- **Never put a `CNAME` on the apex (`@`).** A CNAME at the root legally excludes every
  other record at that name — it would wipe out your `MX` (email dies), your SPF, and
  the Firebase TXT. That is exactly why Firebase gives you `A` records for the apex.
  ALIAS/ANAME is fine; a raw CNAME is not.
- **Cloudflare users: keep the proxy OFF (grey cloud).** An orange-clouded record
  blocks certificate issuance and renewal.
- **Delete leftover parking/forwarding A records** at `@` from the registrar, or the
  old page keeps serving.
- Certificates take **up to 24 hours**. Status moves *Needs setup → Pending → Connected*.
- If verification stalls, check the registrar didn't append the domain twice
  (`thelvlupsports.com.thelvlupsports.com`). Enter `@` or leave the host blank for apex.

### Then authorise the domain for sign-in — do not skip this

**Authentication → Settings → Authorized domains** → add:

```
thelvlupsports.com
www.thelvlupsports.com
```

Keep `localhost`, `<project>.web.app`, `<project>.firebaseapp.com`.

Miss this and Google/Apple sign-in fails with `auth/unauthorized-domain` and phone OTP
fails its reCAPTCHA check — **while email/password keeps working**, which is precisely
why this ships unnoticed and gets discovered by a customer.

If you use Google sign-in, also add to the [Google Cloud credentials console](https://console.cloud.google.com/apis/credentials):
- Authorized JavaScript origins: `https://www.thelvlupsports.com`
- Authorized redirect URIs: `https://<project>.firebaseapp.com/__/auth/handler`

## 8. [OWNER] Email DNS — DKIM, SPF, DMARC

### DKIM

The key below is **408 characters**, which exceeds the 255-character limit for a
single DNS string. It must be **one TXT record containing two quoted strings** —
**not two separate TXT records.** Two records publishes two broken keys and DKIM
fails outright.

| Field | Value |
|---|---|
| Type | `TXT` |
| Host | `google._domainkey` |
| TTL | `3600` |

Most registrars (Cloudflare, GoDaddy, Namecheap, Squarespace, Hostinger) accept the
whole value in one box and chunk it for you. Paste this:

```
v=DKIM1;k=rsa;p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEAuFIqt6liHKmXnoe2NCvtGLCJsu2GK7+QRHw55C/Bk/DyKPuN1lGjbR2MDzIhqStIaVWWWdIZUNayC0JsK02sPjK5Nxis8HkdlaxoeEaO47N4jvvCgQLT2Clfx7x3Bwk8sIsWKQ9/Bgrph5S1zkWs34TGeVSg4Z4LlgQVtxcJ9sevcx8tujrnkkeq2y6WmOeWOTDo1Th7SNilnjJnyFxHOB8Z4GBbKQCLxucmFCNHdNVa5wtwpgiwyWaQozduLyjlTIT3IhyBPtSF/w2HQ2VDVss/2o1Vzm76K2ppvZWAVgO8nXh90hETlMWYOSwjSN40FTSWmEmoqhgky9MAn3ZCXQIDAQAB
```

If your registrar rejects it as too long (AWS Route 53, Google Cloud DNS, some
BigRock/ResellerClub panels), enter it as two strings in the **same** record:

```
"v=DKIM1;k=rsa;p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEAuFIqt6liHKmXnoe2NCvtGLCJsu2GK7+QRHw55C/Bk/DyKPuN1lGjbR2MDzIhqStIaVWWWdIZUNayC0JsK02sPjK5Nxis8HkdlaxoeEaO47N4jvvCgQLT2Clfx7x3Bwk8sIsWKQ9/Bgrph5S1zkWs34TGeVSg4Z4LlgQVtxcJ9sevcx8tujrnkkeq2y6WmOeWOTD"
"o1Th7SNilnjJnyFxHOB8Z4GBbKQCLxucmFCNHdNVa5wtwpgiwyWaQozduLyjlTIT3IhyBPtSF/w2HQ2VDVss/2o1Vzm76K2ppvZWAVgO8nXh90hETlMWYOSwjSN40FTSWmEmoqhgky9MAn3ZCXQIDAQAB"
```

The chunks are concatenated with **no separator**. Don't add spaces. Don't lose the
trailing `=` padding.

Then: **Google Admin → Apps → Google Workspace → Gmail → Authenticate email →
Start authentication.** Google can take up to 48 hours to see the record.

### SPF — exactly one record, at the apex

| Host | Type | Value |
|---|---|---|
| `@` | `TXT` | `v=spf1 include:_spf.google.com ~all` |

A domain may have **one** SPF record. If one already exists, merge into it — do not
add a second. Other senders (SendGrid, Resend…) go before the `~all`. Keep the whole
thing under 10 DNS lookups.

### DMARC — start in monitor mode

| Host | Type | Value |
|---|---|---|
| `_dmarc` | `TXT` | `v=DMARC1; p=none; rua=mailto:dmarc@thelvlupsports.com; fo=1; pct=100` |

Run `p=none` for 2–4 weeks and read the reports, then tighten to `p=quarantine` and
eventually `p=reject`. The `rua` mailbox must exist and accept external mail.

### Verify

```bash
dig +short TXT google._domainkey.thelvlupsports.com @8.8.8.8
dig +short TXT thelvlupsports.com @8.8.8.8
dig +short TXT _dmarc.thelvlupsports.com @8.8.8.8
```

You want **one** DKIM record ending in `IDAQAB`. Two records means the split mistake.
A value cut off mid-base64 means the registrar truncated it.

Then send a message to <https://www.mail-tester.com/> and confirm
`DKIM: PASS with domain thelvlupsports.com` — it must be **your** domain, not gmail.com.

**Hosting and email do not conflict.** Hosting uses `A`/`AAAA` at `@` and `www`; email
uses `MX` and `TXT`. Different record types at the same name is normal. The only rule
is the no-CNAME-at-apex one in §7.

## 10. Appendix — auth bugs to fix before launch [AGENT, after hosting works]

These are **pre-existing bugs in the current code**, not setup steps. Do them only
once hosting is live and verified. Every one has been confirmed by reading the source.

**1. The reCAPTCHA verifier is never cleared — this WILL break OTP in production.**
`analytigo/src/utils/firebase.js` constructs `new RecaptchaVerifier(...)` on the same
DOM node (`au-recaptcha`) on every attempt and never calls `.clear()`. The second
attempt in a session throws *"reCAPTCHA has already been rendered in this element"*.
A user who mistypes their phone number once is stuck until they reload.
**Fix:** cache one verifier module-level, and call `.clear()` in the failure path.

**2. Users see raw Firebase errors.** Every catch does `setNotice(err?.message …)`, so
people are shown `Firebase: Error (auth/invalid-credential).`
**Fix:** map `err.code` to human sentences — at minimum `auth/email-already-in-use`,
`auth/invalid-credential`, `auth/too-many-requests`, `auth/invalid-phone-number`,
`auth/invalid-verification-code`, `auth/code-expired`, `auth/credential-already-in-use`,
`auth/unauthorized-domain`, `auth/operation-not-allowed`.

**3. Phone numbers aren't normalised to E.164.** Firebase needs `+919025867882`. A user
typing `9025867882` gets `auth/invalid-phone-number`.
**Fix:** normalise before sending, defaulting to `+91`.

**4. Consent is collected but never stored.** The sign-up form has an explicit
Terms/Privacy agreement and a separate, unticked model-training opt-in. `upsertUserProfile`
writes a fixed field set and **neither is among them**. You are collecting a DPDP consent
you cannot produce if asked.
**Fix:** persist both with a timestamp and a policy version.

**5. `createdAt` is reset on every login.** `upsertUserProfile` includes
`createdAt: serverTimestamp()` in a `setDoc(..., {merge:true})`, which overwrites it
every time. The code comment claiming otherwise is wrong.
**Fix:** read the doc first and only set `createdAt` when it doesn't exist.

**6. The email-verified check reads stale state.** `onCheckEmail` in `Auth.jsx` tests the
`emailOk` state variable straight after `setEmailOk(...)`, so it reads the previous
render's value — a user who *has* verified sees "verified" and "not verified yet" at once.
**Fix:** assign to a local, then use the local.

**7. The verify screen advances on an empty code.** If sign-up happened without a phone
number, `confirmPhone(null)` returns `true` and any input — including nothing — moves to
"done".
**Fix:** only require and check a code when an OTP is actually outstanding.
